# Phase 2: Sign-up, Login, Sessions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** People on the allow-list can create an account and sign in; everyone else is refused clearly. Every API error is JSON, and the app has the `current_user` / `require_admin` dependencies that Phase 3's data endpoints will use.

**Architecture:** `app/auth.py` holds the security logic with no FastAPI in it: password hashing, session create/resolve. `app/deps.py` adapts it to FastAPI: a per-request DB connection, `current_user` (cookie or Bearer token → user, else 401) and `require_admin` (else 403). `app/errors.py` turns every error into `{"error": "<human message>"}`. `app/routes/auth.py` exposes the endpoints. **Role is read from `allowed_users` on every request, never stored in the session**, so removing someone from the CSV cuts access at the next restart.

**Tech Stack:** FastAPI, stdlib `hashlib.scrypt`, `secrets`, `hmac`, SQLite (schema from Phase 1, unchanged).

**Spec:** `docs/plan.md` sections 2 (Auth, API), 5 (Data model, fail-closed rule) and 6 (API table). Section 9 holds the agreed refusal wording.

## Global Constraints

- Every response under `/api` is JSON. Errors are `{"error": "<message a person can act on>"}`. Never HTML, never a redirect, never a bare 422 or 500 body.
- All endpoints live under `/api` (`/api/auth/signup`, `/api/auth/login`, `/api/auth/logout`, `/api/me`). This is a deliberate change from the brief's suggested `/auth/*`: one prefix means "JSON API", and Phase 4's page router owns every other path. Document it in the README in Phase 6.
- Emails go through `normalise_email` (from `app/loader.py`) at signup **and** login.
- Exact copy:
  - not on the list (403): `This email isn't on Brightline's access list. If you think it should be, ask Dana.`
  - blank email (400): `Enter your email address.`
  - short password (400): `Use a password of at least 8 characters.`
  - already signed up (409): `An account already exists for this email. Sign in instead.`
  - bad login (401, identical for unknown email, not-signed-up and wrong password): `Email or password is incorrect.`
  - no or invalid session (401): `Sign in to continue.`
  - viewer on an admin route (403): `You don't have access to this.`
  - unknown API path (404): `No such endpoint: <METHOD> <path>`
  - unexpected error (500): `Something went wrong on our side. Try again.`
- Password minimum: 8 characters. Hash: `hashlib.scrypt(n=2**14, r=8, p=1, dklen=32)` with a 16-byte random salt, stored as `scrypt$<salt hex>$<hash hex>`. Compare with `hmac.compare_digest`.
- Session token: `secrets.token_urlsafe(32)`. Store only its SHA-256 hex in `sessions.token`. Lifetime 8 hours.
- Cookie: name `fd_session`, `HttpOnly`, `SameSite=Lax`, `Path=/`, `Max-Age=28800`, not `Secure` (localhost over http). The same token is accepted as `Authorization: Bearer <token>` for curl.
- No new dependencies.

## Review Focus

1. **A colleague types their email differently at sign-up and at login** (`" Marcus.Vitale@BRIGHTLINE.example "`). Both must work. Test in Task 3.
2. **Someone removed from the allow-list keeps an old session.** After a restart, it must get 401 (fail closed). Test in Task 3 (a real second boot with a trimmed CSV).
3. **An expired session** must get 401. Test in Task 2.
4. **A garbage token or malformed `Authorization` header** (`Bearer`, `Basic xyz`, `Bearer ` + random text) must get 401, never 500. Test in Task 3.
5. **An empty or non-JSON body on sign-up/login** must get 400 with a readable message, never 422 or 500. Test in Task 1 and Task 3.

### Task 2: Password hashing and sessions (no HTTP)

**Files:**
- Create: `app/auth.py`, `tests/test_auth_core.py`

**Interfaces:**
- Consumes: Phase 1 schema (`users`, `sessions`, `allowed_users`)
- Produces:
  - `@dataclass(frozen=True) CurrentUser(email: str, name: str, role: Role)` with property `can_see_identities -> bool` (`role == "admin"`)
  - `hash_password(password: str) -> str`
  - `verify_password(password: str, stored: str) -> bool`. Returns False (never raises) for a malformed `stored`.
  - `create_session(conn, email: str, now: datetime | None = None) -> str` (returns the raw token; stores its SHA-256)
  - `resolve_session(conn, token: str, now: datetime | None = None) -> CurrentUser | None`. Joins `sessions` → `users` → `allowed_users`. Returns None if the token is unknown or expired, or the email has no `allowed_users` row.
  - `delete_session(conn, token: str) -> None`
  - `SESSION_TTL = timedelta(hours=8)`

from pathlib import Path

import pytest

from app import auth, db
from app.loader import load_allowed_users, load_visits

DANA = "dana.whitfield@brightline.example"

@pytest.fixture
def conn():
    c = db.connect(":memory:")
    db.init_schema(c)
    db.replace_reference_data(c, load_allowed_users(Path("data/allowed_users.csv")), load_visits(Path("data/visits.csv")))
    c.execute("INSERT INTO users VALUES (?, ?, ?)", (DANA, auth.hash_password("correct horse"), NOW.isoformat()))
    c.commit()
    return c


def test_hash_round_trip_and_salted():
    h = auth.hash_password("correct horse")
    assert h.startswith("scrypt$") and h != auth.hash_password("correct horse")
    assert auth.verify_password("correct horse", h) and not auth.verify_password("wrong", h)


def test_verify_malformed_hash_is_false():
    assert auth.verify_password("x", "garbage") is False


def test_session_resolves_to_user_with_role_from_allow_list(conn):
    token = auth.create_session(conn, DANA, now=NOW)
    assert auth.resolve_session(conn, token, now=NOW) == auth.CurrentUser(DANA, "Dana Whitfield", "admin")


def test_token_is_not_stored_in_plain_text(conn):
    token = auth.create_session(conn, DANA, now=NOW)
    assert conn.execute("SELECT COUNT(*) FROM sessions WHERE token = ?", (token,)).fetchone()[0] == 0


def test_expired_session_is_rejected(conn):
    token = auth.create_session(conn, DANA, now=NOW)
    assert auth.resolve_session(conn, token, now=NOW + auth.SESSION_TTL + timedelta(seconds=1)) is None


def test_unknown_token_is_rejected(conn):
    assert auth.resolve_session(conn, "nope", now=NOW) is None


def test_removed_from_allow_list_is_rejected(conn):
    token = auth.create_session(conn, DANA, now=NOW)
    conn.execute("DELETE FROM allowed_users WHERE email = ?", (DANA,))
    assert auth.resolve_session(conn, token, now=NOW) is None


def test_deleted_session_is_rejected(conn):
    token = auth.create_session(conn, DANA, now=NOW)
    auth.delete_session(conn, token)
    assert auth.resolve_session(conn, token, now=NOW) is None

### Task 3: Auth endpoints and the `current_user` / `require_admin` dependencies

**Files:**
- Create: `app/routes/__init__.py` (empty), `app/routes/auth.py`, `tests/test_auth_api.py`
- Modify: `app/deps.py` (add `current_user`, `require_admin`), `app/main.py` (include router), `tests/conftest.py` (add helpers)

**Interfaces:**
- Consumes: everything in `app/auth.py` (Task 2); `get_conn` (Task 1); `normalise_email` (Phase 1)
- Produces (Phase 3 depends on these):
  - `current_user(request: Request, conn = Depends(get_conn)) -> CurrentUser`. Token from cookie `fd_session`, else from a header of exactly the form `Authorization: Bearer <token>`. Otherwise raises 401 `Sign in to continue.`
  - `require_admin(user: CurrentUser = Depends(current_user)) -> CurrentUser`. Raises 403 `You don't have access to this.` for viewers.
  - `router` (prefix `/api`):

| Method & path | Body | Success | Errors |
|---|---|---|---|
| `POST /api/auth/signup` | `{"email", "password"}` | 201 `{"email", "name", "role"}` | 400 blank email / short password, 403 not on list, 409 exists |
| `POST /api/auth/login` | `{"email", "password"}` | 200 `{"token", "user": {"email","name","role"}}` + sets cookie | 401 |
| `POST /api/auth/logout` | none | 204, deletes session, clears cookie | 401 |
| `GET /api/me` | none | 200 `{"email","name","role","can_see_identities"}` | 401 |

  Check order on signup: blank email → not on list → short password → already exists.
  - conftest helpers: `signup(client, email, password="correct horse") -> Response`, `login(client, email, password="correct horse") -> str` (returns the token and asserts 200)
